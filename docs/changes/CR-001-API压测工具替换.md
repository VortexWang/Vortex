# CR-001：API 压测工具由 k6 替换为 Vegeta

- **变更编号 / 修订标识**：CR-001 / V1.11-CR-001（针对 V1.11 的独立工程变更记录，不声称已发布或冻结新的整版规格）。
- **记录日期**：2026-11-02。
- **原基线**：`docs/VORTEX 需求规格说明书 V1_11.md`，SHA-256 `95c73f356841da9a41f9d8bd4ada008497bb1503904792d500701de1898653e5`。
- **用户决定**：在本次初始化会话中，用户明确选择“采用 Vegeta 替代 k6（推荐，MIT，Go 工具链）”，并要求继续。
- **状态**：工具选择已获用户批准；精确版本、完整依赖许可、压测脚本和门槛等效性待工程基线阶段交付及技术评审。未完成评审项不得标为已锁定或验收通过。

## 原因

规格 §14.3 指定 k6 作为 API 压测工具，而 ENGR-002 禁止 GPL / AGPL 第三方依赖。k6 上游采用 AGPL-3.0，Vegeta 上游采用 MIT；选择 Vegeta 避免为 k6 引入许可例外。该决定不放宽 ENGR-002，也不豁免测试镜像、传递依赖和系统包的许可审查。

## 变更范围

实施计划中的 §14.3“API 压测 | k6”采用“API 压测 | Vegeta（Go 测试/脚本负责场景准备、断言和 CI 门槛）”。V1.11 原始文件保持原状，此记录与原件共同交付；在正式契约与版本基线评审时核验该差异，并按规格 §0.3～0.4 完成适用的变更与锁定手续。

没有变更 API 行为、业务功能、规模、性能阈值、验收方法或引擎网络测试工具。Vegeta 不被假定能直接运行 k6 脚本；当前尚无可迁移的项目压测脚本。

## 需求与验收影响

| 项目 | 影响与验证要求 |
| --- | --- |
| §14.3 API 压测 | Vegeta 生成 API 负载；辅助 Go 测试/脚本准备凭据、租户与业务状态，校验响应语义和幂等性 |
| ENGR-001 | 工程前置阶段锁定 Vegeta 及其直接/传递依赖、构建工具和测试镜像精确版本与校验值 |
| ENGR-002 | 审查完整许可清单与 SBOM；不得仅凭 Vegeta 顶层 MIT 判定全依赖图通过 |
| ENGR-003 | Docker 与 GitHub Actions 使用相同提交、测试配置、负载参数与判定入口；任一必要门槛失败均返回非零退出码，保存原始结果 |
| NFR-012～NFR-015、NFR-019～NFR-021 | 适用场景保留规格定义的比例、时间、规模和计量判据；API 请求耗时不能替代最终应用、对账或流量展示的端到端测量 |
| §13.1、NFR-008～NFR-011 | 规模、持续运行和资源稳定性目标保持不变；负载生成与采样方式须记录并可复现 |
| NFR-001～NFR-007、ENGR-005 | 数据面 iperf3、UDP 序列、文件校验、netns/tc 和基准比较不受此变更替代 |
