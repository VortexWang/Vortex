Operations and immutable restriction events enqueue whitelisted safe summaries in the originating PostgreSQL transaction. A deferred constraint trigger locks every affected tenant stream in sorted order only after business writes, assigns contiguous tenant sequence numbers and drains the transaction queue before commit. Global bigserial IDs are internal and never replay cursors. This prevents late commit from skipping a previously allocated sequence and avoids stream-head/business-row or reverse tenant lock cycles. Business/audit/commit failure rolls back both summary and sequence. No in-memory relay or Valkey authority exists. Existing Outbox state transitions use the same committed event producer.

SSE uses stable, domain-separated signed sequence cursors bound to principal/tenant. It reads bounds and event rows in one MVCC statement, has bounded100-row polling,64 streams per process,5-minute connection life,5-second writes and15-second comments. Access/role/state/revocation are checked during polling. Future, malformed, foreign principal/tenant and list cursors are refused. Resync sends the durable high watermark and closes; REST remains authoritative, including unknown operation state and held occupation. Platform replay is audited and audit failure denies admission. TLS shutdown cancels active streams.

A failed delete rolls the floor back. Worker is wired into the separate public serve-http process.
