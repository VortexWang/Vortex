# VORTEX 领域陷阱研究

**领域：** 多租户 TCP / UDP 转发、分布式授权与可信计量  
**研究日期：** 2026-11-02（项目时区）  
**综合置信度：** MEDIUM；外部结论经官方资料核对，`classify-confidence --provider websearch --verified` 返回 MEDIUM。项目安全语义直接来自 V1.11 正文与规范性附录 B；下列防错措施是对该基线的工程推导，不是已实现或已验收声明。

研究结论：最昂贵的错误是把“没收到成功”当成“没发生”，把“到期”当成“消费已结清”。时间、资金来源、执行状态和签发账本必须分别建模，再用持久化证据连接；不能依靠一个全局状态或一个超时任务代替。

## 关键陷阱

### 1. 相对 TTL 与绝对硬边界混算

**错误与成因：** 先将 TTL 裁到政策切换 T、`ownership_until` 或自治截止，再扣安全余量，会制造正常切换空窗；只检查 TTL 则可能越过自治硬截止。把接收时刻当请求起点、序列化 Go 时间后继续当单调时间，也会延长权利。

**预防：** 独立保存请求单调起点、nonce、连接、node/boot、修订，按 `q + ttl − max(0.1×ttl,10s)` 只扣一次余量，再与所有独立边界求交。认证 UTC 区间逐级传播误差，宽度超过 10 秒拒绝新时间敏感消费/签发；重启恢复硬截止并重新认证时间。Go 官方确认单调读数不随序列化保存，不能据此跨进程恢复计时。[Go time](https://pkg.go.dev/time#hdr-Monotonic_Clocks)

**预警：** `time.Now().Add(ttl)` 在响应接收端生成权限；统一 `expires_at` 覆盖所有边界；零 RTT 跨 T 仍固定提前停 10 秒；Hub 重启重新起算 12 小时。

**阶段与验收：** 工程前置 ENGR-004/006 定义时间契约和模型；M0 建可注入时钟门控，M2 验证切换，M3 持久化恢复；NFR-027/033/036/039。12 秒版本保护带只暂停写入并保留会话，不豁免运行、份额或自治硬截止。

### 2. 用全局余额替代逐来源 F/B/L 守恒

**错误与成因：** 将旧负债抵扣新套餐，或把旧承诺保障 L 当成可新发余额；F 内的在外授权、未签发余量、未知负债又被额外相加。一次大余额可以暂时掩盖重复签发。

**预防：** 来源 ID 永不复用，跨来源授权拆成可结算资金分片。逐源维持 `F_s ≤ B_s + L_s`；有效源 `A_s=max(0,B_s−F_s)`，无效源 A 为零，每次增量逐源受 A 限制。L 仅保障原承诺，不能调拨或扩大新发能力。累计定点余数、实际扣费、预留舍入差和 L 更新同事务处理；区分用户实际扣减与 ceil 安全占用。

**预警：** 代码出现 `max(0,sum(B)-sum(F))` 作为新发额度；月度重置清空旧账本；旧源消费扣新源；按每笔授权分别向上舍入用户费用；用浮点累计字节。

**阶段与验收：** 工程前置先验证不变量；M2 锁定原始字节/计费字节接口，M3 实例分片，M4 逐源事务、套餐周期和并发签发；NFR-028/030/035/043、MTR-002/004/013、B.2。回归必须包含旧源 B=0/F=80/L=80、新源 B=50/F=0，仍可从新源委托 50。

### 3. 路径编辑、旧会话与回滚共享可变计费系数

**错误与成因：** grant 只引用 rule_id 或最新路径；改路径后旧授权被新路径消费，历史账单随配置变化，回滚复活旧权限。即使 k 相同，不同路径修订也不能混用原始额度。

**预防：** 编译不可变 `billing_snapshot_id`，绑定租户、规则、执行点、单调路径修订、组顺序/角色、政策版本向量及 k。签发、预扣、批次、final、未知上界贯穿同一 grant/快照。hot/rebuild 的新会话切到新快照，旧会话保留旧路径，并在政策 T 各自换用对应新政策快照；新旧预留分别占用来源。回滚生成更高修订及新快照，不能复用旧 ID。

**预警：** final 通过 join 当前 rules 算价格；快照表允许 UPDATE 内容；仅用 k 判断授权兼容；新路径沿用旧余额；删除规则级联删除未结账快照。

**阶段与验收：** 工程前置契约和模型，M2 会话快照/两阶段切换，M3 签发验证，M4 编译器与结算，M5 展示并存状态；MTR-016、B.5、NFR-044。

### 4. bootstrap 超时释放 activation-unknown，或把 Abort 当撤销消息

**错误与成因：** 首次 Commit 在节点执行但回执丢失，控制端因 120 秒准备超时、`actual_version` 未更新或节点不可达而回收预留；另一节点获得同份资源。只发送 Abort、未落盘互斥栅栏，迟到 Commit 仍可激活。

**预防：** 控制端持久化区分 `prepared / activation-unknown / active / released`，许可可能送达前持久化发送意图和未知占用。节点持久化 Commit 意图；激活与 Abort 串行、幂等且原子互斥。仅接受绑定 apply/boot/修订的可靠“从未激活且迟到 Commit 不可激活”证明，或按全部可能数据权限、续租权及连接占用安全终结。未知按可能 active 处理；重试用更高修订和新 apply，旧未知仍占用。引用按 apply/规则管理，撤销一项不能释放共享份额。

**预警：** 定时器直接 `DELETE reservation`；状态只有 success/failed；发送撤销后立即释放；新 boot 自证旧 boot 未激活；仅等 Commit 许可截止而忽略最后可能子租约。

**阶段与验收：** 工程前置必须先建分离的节点/控制端状态机；M2 引擎幂等激活，M3 持久化栅栏和回执，M4 编排收敛；B.3、NFR-034/042/045。必测许可 120 秒、119 秒激活、回执丢失、131 秒取消仍不释放，以及 Commit/Abort 两种先后。

### 5. 份额交接提前释放差额或复活旧修订

**错误与成因：** prepared 即生效；先停止旧门控再安装新门控；调低连接数后立刻将差额给其他节点；只关闭当前 Hub，遗漏冻结签发方集合中的旧 Hub。

**预防：** 同 tenant/node/kind/boot 线性链仅一笔未终结交接，先占 `max(a,b)`，冻结允许签发方集合并逐一持久化关闭旧修订续租权，旧有效子租约继续运行；节点持久化最低修订及 CAS 意图后原子替换门控。执行回执后才释放速率差额；连接差额还要排空并持久化 enforced。丢回执继续保留最大占用。跨 node/boot 走停止证明或保守安全界，不能使用同主体 CAS 捷径。

**预警：** 两修订并发可用；同数量续期绕过链；连接 draining 时差额已分配；Hub 切换等于份额迁移；自治重分配给别的节点。

**阶段与验收：** 工程前置 ENGR-006，M0 原子门控接口，M2 排空，M3 续租权及重启，M4 全局分配；LIM-004/007/010、B.3、NFR-029/040。

### 6. 恢复轮转复制 R，或等全量对账才恢复续签

**错误与成因：** 把后继 signer_epoch 当新委托复制未签发 R；把封存序号 S 当最终账本；旧 grant 在新 epoch 出现消费又加一次 F。相反，停止续签等待 10～30 分钟对账也会使 5 分钟授权到期而中断合法业务。

**预防：** 单个 SQLite 事务封存前缀、写唯一 transfer、转移同一委托 R 并创建唯一后继；提交后方可响应新授权。旧 A 的消费进后继尾部但仍用原 grant/预留，序号全局单调。generation、signer_epoch、share_revision 分别建模。先重放到检查点 K，再流式追尾；后继可在原 R、未关闭份额链和原硬截止内立即续签。任何凭证/唯一性不明均冻结，恢复先下达封禁/吊销。

**预警：** recovering 统一禁止所有 Hub 签发；恢复事务前响应；重启生成新 transfer 重发 R；`SUM(epoch余额)`；只读前缀后就释放整个委托；恢复时重开已关闭续租权。

**阶段与验收：** 工程前置模型，M3 本地原子轮转，M4 流式对账，M5 真实数据库恢复；B.4、HUB-013/015、NFR-032/041。最小反例：原委托 100、A=30、R=70，轮转前后崩溃与重复转接均不复制 R。

### 7. 开了 WAL 就宣称“先持久化再签发”

**错误与成因：** 应用 COMMIT 成功即响应授权，但 WAL 使用 NORMAL 同步；系统掉电后签发记录丢失，已送达授权仍在外生效。只验证宿主 `sqlite3` CLI 版本，也不能证明 Go 驱动内嵌 SQLite 已修复。

**预防：** 锁定驱动及实际 SQLite 源版本，启动采集 `sqlite_version()`、`sqlite_source_id()` 和生效 PRAGMA。采用含 WAL-reset 修复的版本（推荐 3.51.3+ 的已审查稳定版；官方亦提供 3.44.6/3.50.7 回补，不能把“版本较新”当唯一校验）。安全签发、轮转、拒绝栅栏和确认记录使用 WAL + `synchronous=FULL`，实际连接设置与持久卷必须验证；落盘失败停止相关业务。SQLite 官方说明 NORMAL 在系统崩溃/掉电后可能回滚已提交事务，FULL 在 WAL 提交时同步。FULL 的保证仍依赖文件系统和设备兑现同步，进程 kill 不能代替掉电测试。[WAL 与修复条件](https://www.sqlite.org/wal.html#walreset)、[3.51.3 发布记录](https://www.sqlite.org/releaselog/3_51_3.html)、[同步语义](https://sqlite.org/pragma.html#pragma_synchronous)

**预警：** 依赖默认 PRAGMA；仅对首个池连接配置；容器数据在临时层；签发异步落盘；取走用量即删除内存副本；磁盘满只拒绝新会话，旧会话继续产生不可记账消费。

**阶段与验收：** 工程前置 ENGR-001 锁运行版本；M3 批次/AckUsage、存储失败关停、提交边界故障注入；M6 真实介质/系统故障演练；ENG-039、AGT-006、HUB-003/012、NFR-031。SQLite WAL 不适合跨主机网络文件系统；部署要求同机持久存储。[SQLite WAL 限制](https://www.sqlite.org/wal.html)

### 8. 从备份余额或超时任务“恢复可用性”

**错误与成因：** PG 恢复到旧时间后直接依据备份余额重发；授权到期、失联满 72 小时就释放未知量；将未知上界记成实测流量；补偿用户却未扣平台预算。

**预防：** 先基础备份 + 连续 WAL 物理恢复，再进入维护态对账；核清相关签发方/来源前不从备份余额新发。未知上界继续计 F，与实测分列；精确证据释放未用量，或经批准、足额且实际扣减的平台风险预算在同事务补偿被扣有效余额，生成独立来源及幂等 ID。自动风险预算默认零；迟到精确量仅幂等冲正，不再次补偿。PG 官方确认逻辑 dump 不能作为 WAL 重放的物理基础备份。[PostgreSQL PITR](https://www.postgresql.org/docs/18/continuous-archiving.html)

**预警：** 恢复后自动 normal；disputed 有固定倒计时必解冻；风险补偿只是加余额；WAL 缺口中的兑换码自动重兑；只演练 `pg_dump/restore` 就称物理恢复通过。

**阶段与验收：** 工程前置模型，M4 结算/风险预算/幂等，M5 备份与维护恢复，M6 真恢复及 RPO/RTO；MTR-015、SEC-009/010、NFR-021/024/028/031/032。RTO 与恢复对账窗口须满足自治上限及附录 A 的余量约束。

### 9. 为了尽快展示闭环破坏引擎边界和验收证据

**错误与成因：** 把数据库、续租 RPC 和外部控制请求放入 Engine 热路径，或者先做管理界面、后补可独立测试引擎；开发机 Docker/CI 烟测结果被当成全部 Linux 性能验收。冻结声明被当成附件、编码契约和模型已经存在。

**预防：** Engine 独立 Go 模块，只通过锁定进程内接口收配置/授权/时间、出批次/事件；后端和 Hub 不承载业务流量。性能测试启用正式计量门控，独立记录硬件、CPU 配额、路径、协议/加密、并发、预热/时长、相对基准和原始结果；本机 Docker 与 GitHub Actions 同提交结果分列，资源不足明确未通过。第 13 节的 200 节点/1,000 规则、24 小时稳定性、三中继、UDP 混合负载等不能由小规模用例代替。

**预警：** Engine import 数据库驱动；benchmark 关闭门控；全路径共享 1 Gbps 却解释阈值；mock 恢复代替真实 PG；有限 revision 算例被称为 ENGR-006 完整证明；引用仓库不存在的冻结/评审记录。

**阶段与验收：** 工程前置核实治理证据、锁 ENGR-004 契约与 ENGR-006 故障覆盖；M0～M2 独立数据面退出门槛；M3～M5 逐步集成；M6 严格按第 13 节实测。当前 PROJECT 明确历史评审附件和检查脚本未提供，NFR-038 必须保持待核，不能虚构通过。

## 技术债、集成与安全误区

| 捷径 / 集成 | 风险与正确做法 | 适用阶段 |
|---|---|---|
| 先存 JSON，日后再补授权字段 | 丢失来源、快照、代次、签发集合及证明关联后无法安全迁移；先锁 ENGR-004 编码契约 | 工程前置 |
| 用 Valkey 存余额/幂等事实，消息只靠内存队列 | 缓存丢失会变成重复发放；权威业务事实进 PG，任务与 Outbox 同事务 | M4 |
| 多跳 OPEN 接受报文下游地址、UDP 未 OPEN 就接收 DGRAM | 可绕过路径/鉴权；证书主体绑定上游、跳位/环路校验，下一跳只取本地配置，未开流 DGRAM 丢弃 | M1～M2 |
| 信任自托管入口计量/限速 | 租户可绕过约束；在路径首个平台节点执行门控；全自托管仅豁免计费/份额，仍受身份/运行授权/自治边界约束 | M0～M4 |
| 只在 HTTP handler 检查 tenant_id | 后台任务与直接查询越权；查询层强制 tenantscope，并用故意违规样例证明 CI 能拦截 | M4 |
| Cloudflare 代理模式、只 mock DNS | 违背纯 DNS 转发及真实增删改要求；最小域名权限令牌、加密存储、真实测试域验证 | M5 |
| 升级失败一律回滚二进制 | 新 schema 可能不可逆；兼容检查、排空、保留配置，遇不可逆迁移阻止自动回退 | M3、M5 |
| 沿用规格 k6 而忽略许可冲突 | 用户已批准改用 MIT Vegeta；正式变更记录须落地并映射 ENGR-002/§14.3，冻结原件保持原样；替换工具不豁免 API 压测指标 | 工程前置、M4、M6 |

## 性能与 UX 陷阱

| 陷阱 | 早期信号 | 预防与验证 |
|---|---|---|
| 按每个 TCP/UDP 会话同步请求授权 | 小流吞吐差，Hub QPS 随会话剧增 | 执行点/规则/快照独立水位及自适应预扣；M2 压测确认 D-04 参数，不能擅自锁死默认值 |
| 每跳计费、计读入而不计成功写入 | 多跳费用翻倍、部分写入产生误差 | 按执行点计一次、双向业务载荷写成功提交，UDP 整包预扣/失败整包退回；M0 建基准 |
| DATA 和 DGRAM 共用阻塞窗口或无上界队列 | TCP 满载时 UDP 丢包/延迟失控，内存持续上涨 | 按 ENG-048 独立有界队列和调度份额，混合负载验证 NFR-005；M1～M2 |
| SQLite 长事务、checkpoint 饥饿无观测 | WAL 持续增长、提交延迟、磁盘告警 | 监测 WAL/队列/提交延迟，约束事务长度和 checkpoint 策略，落盘失败停止消费；M3 压测 |
| UI 把 submitted/prepared/recovering 显示为已生效 | 用户看到“成功”却未转发或账本未追平 | 区分期望/实际版本、enforcing/enforced、未知激活、disputed、billing_transition，展示原因及受影响范围；M5 |
| 余额待结算显示固定解冻时间 | 超时后仍冻结却被当故障 | 显示缺少的证明/预算与处理状态，不能承诺无证据固定时长接管；M5 |

## “看似完成”核对表

- [ ] **租约正常续签：** 已覆盖请求延迟、nonce/旧连接/旧 boot、墙钟回拨、版本保护带及硬截止，而非只测 sleep 到期。
- [ ] **首次规则可用：** 空租户从 desired/Prepare 取得 bootstrap；Commit 与 Abort 竞争、回执丢失仍无重复占用或提前回收。
- [ ] **调额不断流：** CAS 只有一个活跃修订、占用 max(a,b)，连接降额排空前不重分差额，跨 boot 不走捷径。
- [ ] **计量“恰好一次”：** 取批、SQLite 提交、Ack、上报确认边界均注入故障；未持久化窗口保留未知上界，没有声称断电可精确恢复所有载荷。
- [ ] **恢复连续服务：** 旧前缀、新尾部和旧 grant 可同时推进，R 只转接一次；恢复前后原硬截止不延长。
- [ ] **模型通过：** ENGR-006 故障及两两组合、覆盖边界/状态数、反例和实现映射有证据；有限脚本与单元测试单独记录。
- [ ] **全量验收通过：** 同提交双端日志、标准资源和 Linux 架构证据、真实 DNS/PG 恢复、24 小时报告齐全；缺失项维持未通过。
- [ ] **治理完成：** 冻结/评审证据及正式契约可定位；Vegeta 变更已记录；构建/镜像/间接依赖许可证、SBOM 与校验值已核对。

## 发生问题后的恢复原则

| 陷阱 | 恢复代价 | 恢复步骤 |
|---|---|---|
| 超发或来源不明 | HIGH | 停相关新签发，隔离源/委托，保留全部账本；重建 F/B/L 和批准预算链，不能直接改余额“对平” |
| Commit/CAS 结果未知 | MEDIUM～HIGH | 保留原最大占用，查询持久化意图及引擎实际状态；只有可靠未激活/停止证明或完整安全截止后释放 |
| 账本损坏或轮转结果不明 | HIGH | 禁止补造 R/后继；先读本地已提交转接记录，无法证明唯一性则冻结，恢复可得前缀与批次 |
| 快照不一致 | HIGH | grant/batch 进入 disputed、保留原预留；按原不可变记录核验，禁止用当前系数重算掩盖 |
| 测试环境不满足基线 | MEDIUM | 保留失败/受限证据，转到满足规格的 Linux 环境复测同提交；不修改阈值解释通过 |
