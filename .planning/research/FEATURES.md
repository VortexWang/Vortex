**领域：** 商业级多租户 TCP / UDP 转发与管理平台

**需求来源：** V1.11 正文、规范性表格和附录 B；附录 A 的默认值及允许范围一并约束实现。

## 结论与使用方式

首版范围已经由规格 §1.4 冻结；本次功能研究的目的，是把这些能力转成可排期、可追踪、可验收的交付集合，不重新挑选市场 MVP。四种转发、全部 TCP / UDP、自治、套餐权益、中文运营界面、真实 DNS 以及恢复都在首版内。下文“基础能力”与“核心特色”均为首版范围，后者不代表可延期。没有引入竞品功能或推断的用户需求。（S1 §0.2～0.4、§1、§14.4；S2 Requirements）

规划应先完成工程版本、五类正式契约和安全模型，再按 §14.4 的 M0～M6 引擎优先顺序推进。M0～M2 通过模拟 Agent 独立驱动引擎；不能为提前搭建业务控制面而使引擎依赖数据库、后端或 Hub。模型实现前置，M4 再以完整通过作为退出门槛；这两个要求同时成立。（GEN-001～GEN-004、ENG-001～ENG-003、ENGR-001、ENGR-004、ENGR-006）

原需求编号沿用，编号缺口不补号，例如正文没有 MTR-012。规范性列表不能因为没有独立表格编号而遗漏：§7.5 五层状态、§9.1 子命令、§11.1 页面、§12.4 六步恢复、§13.1 规模、NFR-005～NFR-007、NFR-025 十四项清单、附录 A/B 均在本文件范围内。本文件按能力归纳，不替代后续 REQUIREMENTS 的逐条原文追踪；正式提取须保留长行、多行单元格、表外编号及规范性列表。

### 计量与授权必须共同交付的细节

1. **口径与来源：** 余额、区域委托、基础流量和流量包用计费字节；节点 grant 为原始字节。路径系数为平台组倍率千分位之和，个人组为 0；仅执行点双向载荷计费，非执行点展示/对账用。签发安全预留 ceil(G×k/1000)，用户扣费使用按租户/资金来源跨授权累积的定点整数部分，余数保留，舍入差仅释放一次。新套餐、月周期、流量包、风险补偿独立不可复用来源；跨来源 grant 拆分。（S1 §10.3～10.4、附录 B.2）
2. **守恒：** F 包括未签发 R、在外未结授权、未知负债，互斥且不二次相加；每来源 F_s≤B_s+L_s，来源有效 A_s=max(0,B_s−F_s)，无效 A_s=0；新委托分片逐来源≤A_s。L 仅保障旧承诺，不能给新来源用，也不能冻结新套餐独立可用额。结算 x、有效来源支付 d、L 承担 x−d 与余数/舍入释放同事务完成。（MTR-004、MTR-013；附录 B.2）
3. **故障承担：** 崩溃留下 U_raw/U_bill，不伪造为用户实测用量，不因租约过期释放；相同消费标识跨账本合并。72 小时仅触发审计处置；平台批准且实际扣足风险预算，才可同事务上界封账并补偿用户有效来源，补偿建新来源。默认自动风险预算为 0。由旧 L 承担部分不再补偿；迟到账本返还平台差额、不重复加用户余额；资金不明/不足/超上界保持 disputed。（MTR-009、MTR-015；附录 B.2）
4. **快照并存：** 执行点变更必须新快照；非执行点换成员而组序列/倍率不变可沿用，但配置/许可仍要满足。run_grant 显式允许旧/新快照集合，旧快照仅供已有合法会话，不让旧配置接新会话。政策 T 变更要为每条存续路径各生成新政策快照，记录完整组政策版本向量及共同有效区间。回滚不复活旧 ID、旧权限、旧负债。（MTR-016；附录 B.5）
5. **准备参数：** 预扣每方向 256KiB→4MiB；每规则/执行点/快照初始 8MiB，其后 max(8MiB,30秒流量)，30%续申；10分钟无会话缩至1MiB、24小时回收须未消费证明；旧路径会话清零后不再为它预发常驻额度。无授权申请最多200ms；D-04 最终数值须 M2 压测评审。（ENG-037、ENG-050；附录 B.5；D-04）

## 功能依赖与阶段安排

箭头 A→B 表示先交付 A，B 才能完成；仅表达技术依赖，不缩减后续验收范围。

```text
需求追踪与治理缺口登记
  → 版本基线 + 数据库/OpenAPI/Protobuf/运行配置/VLink正式契约
  → ENGR-006完整模型及条款/状态机映射
  → 独立模拟Agent与网络/故障/计量基准框架
  → M0直接转发 → M1安全VLink/正反向 → M2多跳/正式门控/两阶段
  → M3真实Agent+Hub → M4业务后端 → M5中文前端+运营 → M6完整验收

租户/身份/权限/节点/组/段许可 → 唯一规则编译器
固定成员与端口事务 → Prepare → bootstrap预留+运行/计费/份额准备 → Commit
不可变快照+逐来源委托 → Hub持久化签发 → Engine预扣/提交 → Agent批次落盘
  → Hub持久化/后端幂等入账 → final/证明未用释放
持久化签发方集合+max份额占用 → 关闭旧续租权 → 同boot CAS回执/连接排空 → 释放差额
全部规则配置+保留端口+健康 → serving → DNS解析集合
自治账本+可信时间+原R/份额/硬截止 → 恢复原子轮转 → 检查点K+尾账追平 → 新委托/normal
后端五层状态+限制/影响/探测 → SSE与中文业务反馈
```

**避免依赖环：** 首次份额候选取持久化期望启用和 Prepare 成功，不等待 actual_version 已 Commit；否则会出现“无份额不能启动、没启动不能拿份额”的死锁。M0～M2 用模拟控制输入，不为了正式后端而反转引擎优先顺序。旧/新快照并存必须先有双预留与来源守恒，不能等 UI 完成才补账本模型。（LIM-009、AGT-010、附录 B.3/B.5）

### NFR-025 十四项逐项覆盖

不得用一个“业务E2E通过”勾选代替以下十四项证据。原文整段保留在后文。

1. 租户隔离与自托管归属：他人资源404；节点或含个人组节点转其他租户拒绝+审计。
2. SEC-003三层权限：API 404/管理403+审计；CI拦直接查询且含故意违规样例分支；节点拒未配置开流并给原因。
3. SEC-011目标地址限制与ENG-049自托管入口可信执行点。
4. ENG-047伪造DGRAM丢弃；ENG-048 TCP满载时同链路UDP达NFR-005。
5. 有安全余量时受限执行点在3个续租周期获更多份额；冻结不可重分；在线同主体CAS不全量断会话。
6. 后端失联、区域额度耗尽、自治硬截止、恢复对账。
7. 单Hub分区/宕机、自治Hub重启/节点重启/政策切换。
8. 端口冲突/保留/安全释放/指定失败建议；入口成员加入/摘除/不可用导致全组规则复检，精确处理DNS集合。
9. 准备失败、部分应用、回滚；运行授权/账号限制/吊销/政策/预留/结算不回滚。
10. 到期/耗尽/降级/离线授权；月度/换套餐旧未承诺作废，未回收承诺逐来源L保障，不扣新来源/不重发。
11. 重启冻结、旧启动停止证明、同boot CAS、未知用量与平台预算补偿。
12. 反向建链断线重连与故障切换。
13. DNS集合与有效成员一致。
14. 空环境部署、升级失败恢复、备份恢复，实测RPO/RTO及恢复窗口不超过自治边界。

**测试方法：** 采用 §14.3 的 Go testing/race/泄漏、Vitest/React Testing Library、Playwright、k6、iperf3、文件校验、UDP序列、netns+tc/故障注入；项目约定同一提交本机 Docker 与 GitHub Actions 分别保存结果。受资源限制、未跑24小时或未获真实Cloudflare/恢复证据，均标未验证，不用模拟结果替代系统验收。（S1 §13、§14.2～14.3；S2 Constraints）
