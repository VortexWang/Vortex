# Phase 1 Plan 06: Retrieve and Verify NFR-038 Originals

## Objective

Resolve NFR-038 using authentic historical records or the specification's formal change process. A newly written search log is not a substitute for original evidence.

## Tasks

### 1. Request and locate originals

Use each evidence-register row to request the listed original review/freeze record or script from its named custodian or the original document handoff. Search any newly identified source location and record the source, date, responsible party, exact path/URL, and result in the search log. Do not mark a record found based only on a filename, recollection, generated reconstruction, or derivative copy without provenance.

**Checkpoint:** The original custodian/source location and actual original files must be available before authenticity verification. If unavailable, leave all affected rows `missing` and the phase blocked.

### 2. Verify each original and update the register

For each recovered item, inspect original file metadata/content and validate the V1.11 §0.4 / Appendix C reference, reviewer, date, result, source hash and evidence links where applicable. Preserve the original file unmodified. Add a stable evidence link and verifier metadata; update only rows whose originals were inspected. Run the fail-closed checker.

If originals cannot be recovered, prepare a formal V1.11 change proposal with requirement impact, rationale, affected acceptance criteria, and approval record. Do not treat the proposal itself as approved.

**Verify:** `python3 tools/phase1/baseline.py evidence` remains blocked for any missing/unverified item and returns passed only after every required original is verified or an approved specification change formally removes the requirement.

### 3. Confirm the gate

Run the shared Phase 1 verification locally and in GitHub Actions for the same clean commit. Confirm NFR-038 status in both archived reports and preserve original hashes/links.

**Verify:** `make phase1-check`; `make phase1-release-gate` remains non-zero until the formal NFR-038 condition is satisfied.

## Threat Model

| Threat | Mitigation |
|---|---|
| Fabricated or derivative evidence is mistaken for an original | Preserve originals, record provenance and hashes, and require inspection of source metadata/content. |
| Missing history is silently treated as acceptable | Fail-closed register/checker and release gate; only approved formal change may alter the requirement. |

| ID | Category | Asset | Severity | Treatment | Mitigation |
|---|---|---|---|---|---|
| T-01-09 | Spoofing | historical review and freeze evidence | high | mitigate | Verify original source, authorship, date, content, and hash before changing an evidence row to verified. |
| T-01-SC | Tampering | NFR-038 status and release gate | high | mitigate | Keep the requirement blocked while any original is missing or unverified; accept a change only with formal approval. |

## Gap Closure

Closes verification gap `G-01-02` only when authentic originals are verified or a formally approved V1.11 change revises NFR-038.
