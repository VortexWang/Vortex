# Phase 1 Plan 05: Close Supply-Chain Candidate Gaps

## Objective

Close the seven unresolved source/integrity/license records without silently changing the user-approved candidate snapshot or lock.

## Tasks

### 1. Verify every unresolved candidate

Inspect all seven entries currently marked unresolved in `docs/governance/version-candidates.yaml`: PostgreSQL image closure, Valkey image closure, SQLite embedded build attestation, SWC composite-license classification, Docker CLI/Compose/Buildx provenance, scratch topology image digest, and network fixture checksum.

For each, record exact version, architecture, authoritative source, immutable checksum or reproducible build attestation, license identifier, license text/source, transitive/system-package scope, and independent verification command. Reject floating tags, unverified summaries, and unsupported license assumptions. Replace a candidate only with a source-verified alternative and document compatibility impact. Keep the existing 43 locked entries unchanged during research.

**Verify:** `python3 tools/phase1/baseline.py candidates` identifies no unresolved record; closure evidence independently reconciles all 50 records and every image/platform digest.

### 2. Review the complete revised candidate snapshot

Recompute the manifest digest after candidate changes and present the complete 50-record manifest, seven closure findings, license policy, and compatibility changes for explicit user approval. Do not edit `version-lock.yaml` to match a changed digest before approval.

**Checkpoint:** Continue to lock creation only after the user approves that exact digest. If rejected, keep the old lock and revise the candidate set.

### 3. Lock and verify the approved snapshot

After approval, update the lock, license policy, closure review, and validator fixtures atomically. Record the approved digest and decision. Run the same governance/build checks locally and in GitHub Actions on one clean commit; archive SBOM and checksums for every final image/platform required by the candidate set.

**Verify:** candidate check and lock check pass; dependency/source/license closure has zero unresolved entries; local Docker and Actions agree on the commit and manifest digest.

## Threat Model

| Threat | Mitigation |
|---|---|
| False provenance, checksum, or license metadata | Prefer authoritative upstream release/source artifacts and independently reproduce/verify checksums; keep unsupported data blocked. |
| Unreviewed candidate drift enters the lock | Bind lock to exact digest and require a new explicit user approval after any manifest change. |

| ID | Category | Asset | Severity | Treatment | Mitigation |
|---|---|---|---|---|---|
| T-01-08 | Tampering | candidate manifest and lock | high | mitigate | Require independent source verification, immutable integrity evidence, full license closure, and approval of the exact digest before lock changes. |
| T-01-SC | Tampering | dependency and image resolution | high | mitigate | Resolve only exact approved versions and digests; reject floating sources, unknown licenses, or unreviewed transitive components. |
