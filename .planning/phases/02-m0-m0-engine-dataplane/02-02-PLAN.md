# Plan 02-02: Linux TCP Splice

<objective>
<goal>
Use Linux `splice(2)` for bare TCPConn pairs while preserving the portable relay API, byte accounting, and directional EOF behavior.
</goal>
<purpose>
Meet the owner-approved Linux TCP development target without weakening half-close or usage accounting.
</purpose>
<output>
Build-tagged splice and portable copy paths with an executable Linux test that exercises splice on the local Docker host and GitHub Actions runner.
</output>
</objective>

<task type="auto">
  <name>Add architecture-scoped splice and portable copy implementations</name>
  <files>engine/relay/tcp.go, engine/relay/tcp_linux.go, engine/relay/tcp_portable.go</files>
  <read_first>engine/relay/tcp.go, .planning/phases/02-m0-m0-engine-dataplane/02-CONTEXT.md, .planning/phases/02-m0-m0-engine-dataplane/02-RESEARCH.md</read_first>
  <action>Add build-tagged Linux amd64/arm64 and portable copy implementations behind copyTCPPlatform. Linux TCPConn pairs use a nonblocking kernel pipe and syscall.RawConn readiness callbacks. Drain each staged pipe chunk before reading more, meter only successful pipe-to-socket splice bytes, and propagate EOF with CloseWrite after the pipe is empty. Return hard syscall errors so TCP closes both endpoints; do not fall back after source bytes may have entered the pipe.</action>
  <verify>
    <automated>cd engine &amp;&amp; go test -race ./... &amp;&amp; GOOS=linux GOARCH=amd64 CGO_ENABLED=0 go test -c -o /tmp/vortex-engine-amd64.test ./relay &amp;&amp; GOOS=linux GOARCH=arm64 CGO_ENABLED=0 go test -c -o /tmp/vortex-engine-arm64.test ./relay</automated>
    <manual>Run the bare-TCP splice regression in the Linux Docker test container and confirm the test passes without a buffered fallback.</manual>
  </verify>
  <done>Linux TCPConn pairs use splice; portable builds continue using the existing copy implementation; half-close and successful-write metering behavior remain intact.</done>
</task>
