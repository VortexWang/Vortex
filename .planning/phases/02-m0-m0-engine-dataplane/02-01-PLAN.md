# Plan 02-01: Independent TCP Relay Tracer

## Goal

Create the first production-shaped Engine slice: an independently buildable TCP relay that proves directional half-close, cancellation, and successful-write metering.

## Tasks

### 1. Create the standalone Engine module and relay contract

Create `engine/go.mod` with Go 1.27.3 and no third-party requirements. Define a small relay API with explicit left-to-right and right-to-left byte accounting. Meter callbacks must run only for bytes accepted by destination writes.

**Verify:** `cd engine && go list -m all` lists only the Engine module; `go test ./...` passes.

### 2. Implement bidirectional TCP forwarding with half-close

Implement two copy directions. EOF on one source shuts down only the matching destination write side when supported; it must not cancel the reverse copy. Context cancellation and non-EOF I/O errors close both connections and wait for both copy workers to exit. Keep the implementation portable and small enough for a Linux splice path to be added behind the same API.

**Verify:** A loopback TCP test sends a request, calls `CloseWrite`, receives a complete response, then observes EOF. Add cancellation and meter-count tests. Run `go test -race ./...`.

### 3. Add the Engine quick-check target

Add a `phase2-engine-quick` Make target that runs Engine unit and race tests without disturbing Phase 1 checks or evidence.

**Verify:** `make phase2-engine-quick` succeeds from repository root.

## Acceptance

- The module uses the selected Go version and no external dependencies.
- Half-close preserves reverse-direction traffic after forward EOF.
- Meter totals equal successful destination writes, including short-write handling.
- Cancellation and hard failures terminate both directions without goroutine leaks.
- Existing `make phase1-check` behavior remains unchanged.
