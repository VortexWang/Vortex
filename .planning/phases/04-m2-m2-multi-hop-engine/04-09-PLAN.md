## Goal

Connect the tested `share.Manager`/`ShareGate` boundary to runtime admission and
path-generation switching. Keep share authority injected and process-local;
this plan does not implement Agent/Hub persistence.

## Implementation Detail

1. Extend role config with share revision, node/boot fencing and lease payloads;
   reject stale, cross-boot and missing lease inputs before OPEN.
2. Construct the ShareGate alongside the source policy Gate. Admission reserves
   rate/connection shares atomically; close, abort and route changes release
   only after the manager proves the correct lease and generation.
3. Exercise duplicate Prepare/Commit/Abort, CAS conflicts, activation-unknown,
   middle-hop restart, old TCP drain, new-generation rejection and UDP reopen.
4. Add Docker/Actions evidence with active/draining occupancy, transaction IDs,
   lease proofs and no double-release assertions.

## Verification

Run `go test -race ./runtime/accounting ./runtime/relay ./runtime/config ./share ./cmd/vortex-relay`, the recovery topology, and the same-SHA Actions workflow. A stale receipt, duplicate allocation, or premature release must fail the run.
