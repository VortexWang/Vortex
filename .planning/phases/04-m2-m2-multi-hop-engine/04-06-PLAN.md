## Goal

Close the Phase 4 qualification gap with a runtime-backed UDP path and a
reproducible mixed TCP/UDP workload over the exact five-process topology.
Produce comparable same-path baseline results and reconcile successful bytes
against the in-process accounting evidence. Do not call NFRs passed unless the
host, workload, data path and all acceptance thresholds are recorded.

## Research Findings

- The current runtime exposes TCP `service_listen` only. `openRequest` sets
  network 1, and `Service.serveStream` explicitly rejects network 2.
- VLink has `WriteDgram`, but runtime source, relay bridge and destination target
  handling do not establish UDP sessions.
- `BridgeConnWithGate.reserve` opens a new accounting session for every chunk;
  a flow must instead have one bounded session lifecycle with stable evidence.
- The qualification benchmark currently measures VLink library TCP and
  loopback UDP separately. It does not create sustained mixed load through the
  three relays and cannot establish fairness, NFR-005 loss, or same-path ratio.
- Native Ubuntu topology/accounting smoke passed on `86f06b3`; Actions passed
  the receive-race fix on `b4b484e`. Both are prerequisite evidence, not the
  missing mixed-load qualification.
- After adding UDP, one run completed both payload checks and byte reconciliation
  but relay logs also reported repeated stream-violation closure during teardown.
  The trigger must be isolated and classified before treating repeated smoke or
  mixed-load results as clean; do not raise protocol limits to hide it.

## Execution Progress

- Implemented source UDP sessions, relay DGRAM forwarding, destination UDP
  target support and TCP/UDP accounting reconciliation for one smoke payload
  each. Native Ubuntu and Actions both passed this functional smoke on
  `9ddb724`; Docker Compose was not executable locally because Docker Desktop's
  daemon socket was unavailable.
- Fixed stale WINDOW and duplicate RST handling and added explicit local stream
  reset cleanup. Focused lifecycle tests passed 100 race-enabled repetitions;
  full `go test -race ./...` passed.
- Still open: sustained mixed load, same-path baseline, queue/fairness and loss
  counters, Docker Compose run, and D-04/NFR review. No performance NFR is
  qualified by the smoke result.

## Tasks

1. Extend strict runtime config and the single relay binary with bounded UDP
   source sessions. OPEN/OPEN_OK must precede DGRAM; local target selection
   remains policy-owned. Sessions expire and close on path/link loss without
   replaying opaque datagrams.
2. Implement relay/destination DGRAM forwarding with independent bounded UDP
   queues, drop classification and counters. Preserve TCP forwarding and
   half-close behavior under concurrent load.
3. Give each accepted TCP/UDP flow one accounting session. Reserve before
   sending, commit only accepted bytes/datagrams, retain unknown reservations,
   and emit stable flow and aggregate totals without private/high-cardinality
   metric labels.
4. Add a deterministic workload driver that runs TCP-only baseline and
   simultaneous TCP+UDP over the same route, config digest and duration. Report
   throughput, first-byte latency, UDP sent/received/loss, queue drops, flow
   counts and accounting reconciliation. Fail closed for missing roles,
   nonzero drops without classification, accounting mismatch or incomplete
   artifacts.
5. Run Docker Compose and native Ubuntu on the same clean SHA and workload;
   run the same Make target in GitHub Actions. Upload raw samples, normalized
   report, topology/config digests and checksums. Record host resources and
   classify hosted/virtualized results separately from dedicated hardware.
6. Compare results with the Phase 4 NFR thresholds and same-path baseline.
   Keep NFR-003/005/006/007 and D-04 unqualified where the host or evidence
   cannot establish the threshold. Do not silently convert a short smoke run
   into a qualification pass.
