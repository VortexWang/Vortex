## Goal

Close the Phase 4 qualification gap with a runtime-backed UDP path and a
reproducible mixed TCP/UDP workload over the exact five-process topology.
Produce comparable same-path baseline results and reconcile successful bytes
against the in-process accounting evidence. Do not call NFRs passed unless the
host, workload, data path and all acceptance thresholds are recorded.

## Research Findings

- The current runtime exposes TCP `service_listen` only. `openRequest` sets
  network 1, and `Service.serveStream` explicitly rejects network 2.
- VLink has `WriteDgram`, but runtime source, relay bridge and destination target
  handling do not establish UDP sessions.
- `BridgeConnWithGate.reserve` opens a new accounting session for every chunk;
  a flow must instead have one bounded session lifecycle with stable evidence.
- The qualification benchmark currently measures VLink library TCP and
  loopback UDP separately. It does not create sustained mixed load through the
  three relays and cannot establish fairness, NFR-005 loss, or same-path ratio.
- Native Ubuntu topology/accounting smoke passed on `86f06b3`; Actions passed
  the receive-race fix on `b4b484e`. Both are prerequisite evidence, not the
  missing mixed-load qualification.
- After adding UDP, one run completed both payload checks and byte reconciliation
  but relay logs also reported repeated stream-violation closure during teardown.
  The trigger must be isolated and classified before treating repeated smoke or
  mixed-load results as clean; do not raise protocol limits to hide it.
