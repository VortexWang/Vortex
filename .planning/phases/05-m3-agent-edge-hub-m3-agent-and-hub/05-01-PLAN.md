# Plan 05-01: Startable node and durable local store

## Goal

Create the first production-shaped tracer: one `vortex-node` binary with Agent and Engine boundaries, a protocol-test Hub, boot identity, and independent Agent/Hub SQLite WAL stores.

## Tasks

1. Extend the control contract with explicit versioned registration, HELLO/heartbeat, authorization, usage batch/ACK, apply result and error/idempotency fields. Update versions and requirements mapping; reject unmapped Phase 5 IDs in CI.
2. Add an Agent/Hub package layout and process-internal Engine interface. Agent creates a fresh boot_id, loads identity/config, and supervises Engine lifecycle without database access from Engine.
3. Implement SQLite stores with WAL, FULL durability for ledger/authorization/receipt writes, bounded connections, busy timeout, schema versioning, and runtime evidence for SQLite version and compile options. Keep Agent and Hub databases separate.
4. Add a protocol-test Hub and `vortex-node` command that starts, exchanges heartbeat/config, records a durable event, and shuts down cleanly in Docker.

## Verification

- `go test ./...` in each Go module and `go vet ./...`.
- Start/stop tracer test proves Engine remains usable through the formal in-process interface and no database package is imported by Engine.
- SQLite reopen/crash fixture proves a committed event survives and an uncommitted transaction is not ACKed.
- Same SHA Docker and Actions smoke, with JSON evidence and SQLite runtime details.

## Must Haves

- Startable `vortex-node` and protocol-test Hub.
- Versioned control contract with every Phase 5 contract requirement mapped or explicitly justified.
- Independent Agent/Hub SQLite WAL stores with FULL commit boundary.
