# Plan 05-04: Ledger handoff, activation recovery and evidence gate

## Goal

Make recovery and activation unknown states durable, replayable and auditable, then prove the runtime boundary in reproducible Docker/Actions tests.

## Tasks

1. Implement activation states prepared, committing, activation-unknown, active, aborted and released. Persist transaction IDs, fencing lower bounds, resource holds and Engine query results; only a proof of inactive state permits release.
2. Implement restart recovery with a fresh boot_id: recover ledger and trusted time, report old boot records, re-Prepare, obtain valid grants/shares, Commit and record activation. Never infer old process termination from boot_id alone.
3. Implement Hub recovery: revoke/restrict first, atomically seal the old ledger prefix to S, create one transfer record for R to the next signer_epoch, replay prefix and tail by unique IDs, advance a confirmation checkpoint, and retain unresolved/争议 records.
4. Add crash/kill, lost Commit receipt, duplicate Prepare/Commit/Abort, late receipt, full disk, revocation and handoff evidence tooling. Mark the Hub as protocol-test-only until Phase 6.

## Verification

- Deterministic state-machine and race tests show no dual active generation, duplicate transfer, premature release or lost confirmed ledger.
- Restart fixture proves activation-unknown and unknown liabilities remain occupied.
- Docker and GitHub Actions use the same SHA, save raw logs, ledger hashes, SQLite details and verdict JSON.
- `make phase5-check` fails closed on missing evidence and does not claim production backend authority.
