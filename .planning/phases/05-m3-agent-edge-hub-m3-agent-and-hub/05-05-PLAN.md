## Threat Model

- **Contract spoofing or downgrade:** compare the exact approved content hash, enforce SemVer and reject unapproved fields or versions before decoding updates.
- **Duplicate or replayed config update:** bind durable results to transaction ID, message ID, version and fencing generation; replay only the stored result.
- **Unknown activation outcome:** preserve activation-unknown and old/new holds across restart; never use timeout or boot ID as proof of inactivity.
- **Malicious or partial upgrade artifact:** verify signature and digest before stage, sync staged files, activate atomically, and retain the old binary until health success is durable.
- **Rollback authority loss:** exclude confirmed receipts, revocation, fencing and unknown liabilities from compatibility snapshots; irreversible migrations prohibit automatic rollback.
